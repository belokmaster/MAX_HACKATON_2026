# Умный город ЖКХ — Сервис для платформы MAX

Интеллектуальная система автоматизации взаимодействия жителей многоквартирных домов, управляющих компаний (УК) и аварийных служб на платформе мессенджера MAX.

---

## 1. Описание решения

Сервис решает проблему долгой обработки заявок жителей в ЖКХ, устраняет перегрузку диспетчерских служб и обеспечивает прозрачный процесс вызова мастеров.

### Ключевой функционал:
1. **Автоматическая идентификация и привязка к УК**:
   - При первом обращении пользователь указывает адрес дома.
   - Система сопоставляет адрес с реестром домов и закрепляет жильца за его управляющей компанией.
   - При неточном вводе бот предлагает список подходящих адресов в виде интерактивных кнопок.

2. **Интеллектуальная классификация проблем**:
   - Система анализирует текст жильца и определяет категорию работ: сантехника, электрика, лифтовое хозяйство, плотницкие или общедомовые работы.
   - Разделение зон ответственности согласно Жилищному кодексу РФ и Постановлению № 491:
     - **Зона ответственности УК (общедомовое имущество)**: стояки, щитки в подъезде, кровля, лифты, освещение в местах общего пользования — работы выполняются бесплатно.
     - **Зона ответственности жильца (внутриквартирное имущество)**: смесители, розетки, внутренняя проводка — предлагается платный вызов мастера УК с фиксированным начальным тарифом.
     - **Аварийные ситуации**: прорыв магистральных трубопроводов, запах газа, открытое искрение силовых кабелей — мгновенное оповещение и вывод прямых телефонных номеров дежурных аварийных служб.
   - Интерактивный диалог уточнения (до 2 шагов), если контекст обращения неоднозначен.

3. **Планировщик смен с распределением сквозной нагрузки**:
   - Вызов мастера осуществляется по дням и сменам: Утро (09:00 — 13:00) и День (13:00 — 18:00).
   - Специалисты могут обслуживать как одну, так и несколько УК одновременно (например, узкие специалисты: лифтеры, плотники).
   - Нагрузка мастера учитывается сквозным образом во всех закрепленных за ним УК: занятость слота в одной компании автоматически уменьшает лимит мастера для остальных компаний.
   - При отмене заявки слот мастера автоматически освобождается для повторной записи.

4. **Полное управление в диалоге бота**:
   - Просмотр всех созданных заявок и их статусов по команде `/status`.
   - Возможность отмены активной заявки одним нажатием кнопки.
   - Режим диспетчера по команде `/admin` для авторизованных сотрудников.

## 2. Архитектура и технологии

- **Бэкенд**: Python 3.12, FastAPI, Pydantic v2, HTTPX.
- **Интеграция с платформой MAX**:
  - Работа строго по протоколу **Webhook** (`POST /webhook`).
  - Проверка секретного ключа подписи в заголовке `X-Max-Bot-Api-Secret`.
  - Мгновенный ответ `200 OK` (до 30 секунд по требованиям платформы) с асинхронной обработкой через `BackgroundTasks`.
  - Обязательный вызов `POST /answers?callback_id=...` для предотвращения зависания интерактивных кнопок.
  - Поддержка доверенных корневых сертификатов Национального удостоверяющего центра (НУЦ Минцифры России).
  - Rate-limiter исходящих сообщений (не более 2 сообщений в секунду на чат).
- **Прокси-сервер**: Caddy с автоматическим выпуском и обновлением TLS/HTTPS-сертификатов Let's Encrypt.
- **Хранилище данных**: JSON-хранилище на постоянном диске (`data/users.json`, `data/appeals.json`) — быстрое развертывание и энергонезависимость без необходимости настройки тяжелых СУБД.
- **Соответствие спецификациям**:
  - `openapi.yaml` — полная спецификация OpenAPI 3.1.
  - `DATA-API.yaml` — контракт автоматической проверки жюри хакатона.

## 4. Быстрый старт и запуск

### 4.1. Подготовка конфигурации
Скопируйте пример файла конфигурации:
```bash
cp .env.example .env
```

Заполните переменные в файле `.env`:
- `BOT_TOKEN` — токен вашего бота, полученный от платформы MAX.
- `WEBHOOK_SECRET` — произвольная секретная строка для проверки подлинности вебхуков.
- `WEBHOOK_URL` — публичный URL вебхука: `https://your-domain.com/webhook`.
- `DOMAIN` — доменное имя вашего сервера для Caddy.
- `ADMIN_USER_IDS` — ID администраторов через запятую (например, `12345678,87654321`).

### 4.2. Запуск через Docker Compose
Запуск всех сервисов в фоновом режиме:
```bash
docker compose up -d --build
```
Сборка занимает менее 2 минут благодаря оптимизированному Dockerfile на базе `python:3.12-slim`.

При старте контейнер `api`:
1. Устанавливает корневой сертификат Минцифры РФ в доверенные.
2. Инициализирует локальные хранилища данных.
3. Автоматически регистрирует вебхук в платформе MAX.
4. Настраивает меню команд бота (`/start`, `/help`, `/status`, `/admin`).

## 5. Сценарии проверки функционала

### Сценарий 1: Первичная регистрация и ввод адреса
1. Отправьте боту команду `/start`.
2. Бот запросит адрес проживания.
3. Введите: `ул. Пушкина, д. 10`.
4. Бот подтвердит привязку к УК «Комфорт» и предложит описать проблему.
*Если ввести часть адреса (например, `Ленина`), бот предоставит кнопки выбора подходящих домов.*

### Сценарий 2: Заявка по зоне ответственности УК (бесплатно)
1. Напишите: `Не работает свет в подъезде на третьем этаже`.
2. Бот определит категорию «Электрика» и зону «УК (бесплатно)».
3. Бот отобразит интерактивные кнопки с ближайшими доступными сменами:
   - `Завтра, 24.09 (Утро 09:00 — 13:00)`
   - `Завтра, 24.09 (День 13:00 — 18:00)`
4. Нажмите на выбранную смену.
5. Бот создаст заявку со статусом «Назначена» и сообщит номер заявки.

### Сценарий 3: Заявка по зоне жильца (платная услуга)
1. Напишите: `Потек смеситель в ванной`.
2. Бот определит категорию «Сантехника» и зону жильца, уведомит о стоимости от 500 рублей и предложит выбор:
   - `Записаться к мастеру`
   - `Отмена`
3. При нажатии на запись бот выведет доступные смены и зафиксирует вызов.

### Сценарий 4: Экстренная ситуация (Авария)
1. Напишите: `Прорвало трубу отопления, хлещет кипяток`.
2. Бот мгновенно переведет обращение в категорию «Аварийная ситуация» и предоставит прямой телефон круглосуточной аварийной службы без ожидания записи.

### Сценарий 5: Просмотр и отмена заявок
1. Отправьте команду `/status`.
2. Бот отобразит список активных заявок с адресом, категорией и временем смены.
3. Под каждой активной заявкой отображается кнопка `Отменить заявку`.
4. При нажатии заявка отменяется, а слот мастера освобождается в планировщике.

## 6. REST API эндпоинты

Сервис предоставляет REST API для интеграции с внешними системами и автоматической проверки жюри:

- `GET /api/health` — проверка работоспособности сервиса.
- `GET /api/appeals` — получение списка всех заявок (с фильтрацией по `user_id`, `uk_id`, `status`).
- `POST /api/appeals` — создание новой заявки.
- `GET /api/appeals/{id}` — получение информации о заявке по ID.
- `PATCH /api/appeals/{id}` — обновление статуса или параметров заявки.
- `DELETE /api/appeals/{id}` — удаление заявки.
